## Curated release notes

This major project release adds recoverable atomic email acceptance and isolated
synthetic no-send recording while retaining legacy HTTPv1 behavior.

### Compatibility

PHP minimum changes from^8.2 to **^8.4**, with an explicit PDO MySQL requirement.
Service CI targets PHP8.4/8.5. The project uses a committed Composer lock and the
email-delivery1.2.0 engine. This runtime break, approved by the owner, is why the
project target is2.0.0; HTTPv1/v2 are independently versioned contracts.

### Added

- Keyed atomic v2 acceptance with a stable receipt and same-key lookup. Identity
  comes from operator-owned consumer bindings and survives API-key rotation.
- Optional encrypted synthetic recording in an isolated package-owned table,
  explicit retention and a bounded trusted cleanup CLI. It never creates a mail job.
- Raw HTTP shape validation, real MySQL/Redis/auth/DI/worker integration, uncertain
  commit recovery and independent-process contention/isolation verification.

### Fixed and clarified

- Textual APP_DEBUG=false hides exception details in responses while server logging remains.
- Ambiguous numeric-keyed/empty nested JSON objects are rejected before array conversion.
- Public installation/upgrade/configuration examples, welcome template context,
  fixed-window terminology and PHP8.5 diagnostic compatibility are aligned.

### Guarantees and limits

Queue acceptance is not rendering/SMTP/mailbox confirmation. Retained real receipts
must outlive queue cleanup; preserve same intent/key and read keys for recovery.
Synthetic repeated/uncertain calls can append extra inert records. Their timing
is not constant or proven equivalent to either real API. Consumer public responses,
account eligibility and host durable intent remain separate integration work.

## Upgrade and enablement

Read [upgrade2.0.0](../upgrade/2.0.0.md) before deployment. Real v2 requires service004
bindings then installed-package002/003; optional synthetic uses installed-package004
and explicit retention/maintenance. No automatic migration/backfill/cron is added.
Restart workers and clear compiled caches through the deployment process. Never
use schema deletion or new keys as a shortcut for uncertain acceptance recovery.

After exact2.0.0 publication only:

```bash
composer create-project --prefer-dist --no-dev maatify/channel-delivery channel-delivery 2.0.0
```

Before publication use a reviewed source checkout; do not present that command as
currently available merely because the target exists.
